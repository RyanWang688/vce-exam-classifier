## 第 8 轮：2026-11-06，用规则判定复核

第 7 轮的置信度全在 0.85 到 0.95，无法用来判断。这轮不再让模型给分类打分，改为回答可检验的问题：

- `topic_fit`：`clear`（一个知识点覆盖至少三分之二分值）、`split`（超过三分之一分值属于其他知识点）、`poor`（没有合适的知识点）。
- `alternative_topics`：其他涉及的知识点，会校验是否在分类表内。
- `reason`：一句话依据。

`confidence` 改为只表示题目是否读准。需要复核的题由页面规则判定，并写明原因；管理员可以只看这些题。

## 第 4 轮：2026-11-06，支持 Word（.docx）

**完成内容**

- 页面可以上传 `.docx`，在浏览器里解析正文、表格、自动编号和内嵌图片。
- Word 公式（OMML）转成 LaTeX 发给 Gemini。
- 内嵌图片随正文一起发送，Gemini 返回图片 ID，直接作为题目配图，不需要第二轮定位。
- 读不到的图片可以手动上传替换。

**查证后做出的决定**

| 决定 | 原因 |
|---|---|
| 解析 docx 内容，不做 docx 转 PDF | 浏览器里没有可靠的转换方式；云端转换会把试卷发给第三方 |
| 不直接把 docx 发给 Gemini | 官方文档只说明了 PDF 的处理方式 |
| 自己解析公式和编号，不用 mammoth 等库 | 通用库容易丢公式和自动编号，而题号决定切题和 `source_id` |
| 配图直接取内嵌文件 | 比裁剪更清晰，也没有坐标误差 |
| Word 模式下手动操作改成上传图片 | docx 没有固定页面，无法框选 |
| 页码固定为空 | docx 的分页取决于打开它的软件 |
| `.gitignore` 增加 docx 和导出 ZIP | 仓库已公开，防止试卷被误提交 |

**测试情况**

- 真实 Word 文档：VCAA 的 Mathematics、Physics、Biology Study Design 共 254 个公式，全部能被 KaTeX 解析。
- 合成文档：自动编号（重新计数、样式编号）、修订删除、兼容内容、表格、EMF 图片。
- 回归：PDF 流程正常。
- **已知限制：**
  - MathType 等 OLE 公式读不到，Mathematics Study Design 里有 122 个。页面会提示改用 PDF。
  - EMF/WMF 图片无法显示，Word 原生形状、图表也取不到，需要手动上传。
  - Word 里裁剪过的图片会以原图导入。
  - 页眉、页脚、脚注不会读取。
- **没测过：** 真实 Word 试卷经过 Gemini 分析的效果。Wix 版本暂不支持 docx。

**图片格式补测（第 4 轮修正）**

| 格式 | Word 内嵌 | 手动上传 |
|---|---|---|
| PNG、JPG、JPEG | 保留原文件 | 可用 |
| WebP、GIF、BMP | 转成 PNG | WebP、GIF 可用，BMP 未测 |
| TIFF、WMF、EMF | 读不到，提示手动上传 | 未测 |
| 损坏的文件 | 修复后读不到，提示手动上传 | 修复后拒绝并提示 |

补测发现损坏的 PNG 会被当成正常图片发给 Gemini，可能导致整次请求失败，已改成先解码确认。

测试用的 TIFF、WMF、EMF 只是几个字节的假文件。VCAA 文档里的真实 WMF 是公式预览，走 MathType 提示，没有进入这条读取流程。真实文档的图片只有 JPG/JPEG，PNG 只用程序生成的图片测过。所有图片都还没有真正发给过 Gemini。

## 第 2 轮：2026-11-06，题目配图自动截图

**完成内容**

- 第一轮分析增加 `figures`：每张图所在的 PDF 页、描述和所属小问。
- 第二轮定位：用 PDF.js 渲染含图页面，发给 Gemini 取 `box_2d`，再在浏览器裁剪成 PNG。
- 卡片显示截图，支持调整、删除、手动添加。
- 新增“导出 ZIP（含图片）”；JSON 内嵌 base64；CSV 写图片文件路径。

**查证后做出的决定**

| 决定 | 原因 |
|---|---|
| 渲染页面后裁剪，不提取 PDF 内嵌图片 | 函数图、电路图常是矢量图，扫描件整页是一张图，提取不到 |
| 定位时发页面图片，不发原始 PDF | 官方只为图片说明了 `box_2d`，没有 PDF 的说明；而且坐标必须和裁剪的图一致 |
| 每批最多 6 页合并请求 | 节省频率额度；官方说明内联请求总大小上限 20MB |
| 坐标四周外扩 12（千分比） | 避免切到坐标轴和标注 |
| 定位失败不影响分类结果 | 分类先展示；失败时提示手动框选 |
| 429 带 `retryDelay` 时自动重试一次 | 第二轮更容易碰到频率限制，等待不超过 60 秒 |
| 渲染用 `intent: 'print'` | 默认依赖 `requestAnimationFrame`，页面在后台时渲染会暂停 |
| Wix 暂不迁移截图 | 先验证定位精度，再决定怎么迁移 |

**查证后做出的决定**

| 决定 | 原因 |
|---|---|
| 默认模型 `gemini-3.6-flash` | 官方标记为稳定版，有免费层；`gemini-3.8-flash` 较新，标记为 New |
| 继续用 `generateContent` | 官方推荐新项目用 Interactions API，但说明 `generateContent` 仍完全支持 |
| REST 字段用 `inlineData` / `mimeType` | `generateContent` 官方示例是 camelCase |
| 不发送 `temperature` | 官方说明 3.6+ 会忽略该值，未来会返回 400 |
| 不设置 `thinkingConfig` | 各模型允许的取值不同，先用默认值观察 |
| 保留 20MB 上限 | 需求规定。官方写的是 PDF 50MB，以后可以放宽 |
| `topic` 不用 schema 枚举 | 80 个枚举值有触发 schema 过大的风险。改由提示词约束，前端校验并标红 |
| 公式定界符用 `\( \)` | General Maths 的 `$` 金额不会被误判成公式 |
| Wix 改成任务 + 轮询 | Wix 后端请求上限 14 秒且无法提高 |
| Wix 用 `wix-secrets-backend.v2` | 旧的 `getSecret` 已标注弃用 |

**测试情况**

- 真实接口：用无效 Key 调用，确认浏览器跨域可用、Key 错误提示正确。

- **没测过：** 真实 Key 下的 PDF 分析，所以 `responseSchema` 尚未经过 Gemini 实际校验，分类效果也还没有数据。
