## 第 38 轮：2026-11-25，手写题

**为什么这样分工**

本地的 Tesseract 只认印刷体，手写公式基本认不出；浏览器里能跑的手写公式模型几百 MB、在 CPU 上很慢。所以：

- **本机**（每页约 0.2 秒）：
  - 去光照不均：除以模糊后的背景，纸纹、横线、方格、阴影变白；去掉贴着图片边缘的黑边。
  - 拉直：在 ±6 度里找行最分明的角度。
  - 去掉笔记本边线、装订阴影这类很长的竖线；很长的横线只在找块时不算。
  - XY 切分找出每一块手写：先切行、每行切列、每块里面再切，双栏也能分开。
  - 按块精确裁图；对账每一块的去处。
- **Gemini**（每页 1 次，最多 3 页同时）：
  - 看左边标了 B1、B2… 的页面，说哪些块属于哪道题、哪些是解答、哪些无关。
  - 把题目转成文字和 LaTeX，并分类。
  - 看不清的字标 [?] 并说明。

页面上显示的是原手写裁图，和原稿一样；转出的文字只用于分类和检索。每一块都要归到某道题、解答或无关内容；没归属、重复归属、有看不清的字的题，都提示“裁图请看一眼”。手写页统一用整理过的页面，手动调整裁图、从题库重新打开都按它（重新打开时同样的输入会整理出同样的页面）。网站版的 Gemini 调用照常经后台。

**测试数据**（只放在被忽略的 `tmp-fixtures/`，用 `tests/fetch-handwriting.ps1` 下载）

- MathWriting VLM pages（CC-BY-4.0）验证集 9 页：真人手写公式，拍照效果（阴影、倾斜、横线纸），8 页带编号、1 页双栏无编号，每道附标准答案 LaTeX，共 60 道。
- English Handwritten Math Notes（CC-BY-4.0）4 页：真实手写的线性代数笔记扫描件。

**本机部分**：13 页每页 0.14–0.25 秒，块数都不少于题数（没有把两道题并成一块）。测试中修好的问题：

| 问题 | 修法 |
|---|---|
| 双栏页右栏的高公式把左栏上下两道题连成一块 | 改为 XY 递归切分 |
| 笔记本的浅色边线（断断续续）把整页连成一块 | 竖线允许 8 像素以内的断口，七成以上是实的就算线 |
| 扫描件右边的装订阴影、纸背透过来的淡痕把相邻行连起来 | 页边大半页都有墨迹的列去掉；一行只有零星几个墨点不算有字 |
| 纸边残线被当成一块、又没有归属，误报“裁图请看一眼” | 贴着页面上下边缘的扁条不算 |

**加上 Gemini（gemini-3.6-flash 免费层）**

- 切题：带编号的 8 页，52 道题全部切出，题号全部正确，没有多切、少切、合并；双栏无编号页改进后 8 道也全部切出，阅读顺序正确。裁图逐题看过：完整、只含本题、阴影纸纹都去掉了。
- 转写（和标准答案比，同义写法算相同）：
  - 第一版：52 道里完全一致 6 道，平均字符相似度约 0.77。
  - 错误主要是：Gemini 把题号写进了文字；上下标、撇号漏掉；希腊字母和拉丁字母认混（ω/w、ε/E、θ/Θ、τ/T、ζ/s）；数字和字母认混（9/q、46/u₆）。
  - 发现标注图上画的红框和上划线混在一起。
  - 改进：不画框只写编号；去掉文字开头的题号；提示词点明这些易错处；没有题号的一条条式子也当题收录。
  - 改进后重跑的 6 页（共 40 道）：完全一致从 2 道升到 19 道，平均相似度从约 0.61 升到约 0.82（改进前双栏页一道都没认出）。另有 3 道“漏上划线”是标准答案错了（原图里没有上划线，已截图核对），1 道 binom 和 pmatrix 显示相同；算上这 4 道是 23/40。
  - 剩下的错误多是手写本身就模棱两可的字（σ/θ、ζ/ρ、e/l），这套测试是随机拼的公式，没有上下文；真实题目有句子和上下文，应会更好。
- 速度：每页 20–33 秒（主要是 Gemini 的思考时间），多页同时进行。
- 稳定性：同一页偶尔整页回答“没有题目”（双栏页第一次就这样）→ 页面上有好几块手写却没有题时，提醒后自动再问一次。
- 免费层当天约 22 次后用完额度，mw-4、mw-7、mw-12 三页没能用改进后的版本重跑。

**还没做 / 可以再提高的**

**做了什么**

- **组卷导出 Word**：组卷页“导出 Word”，和打印用同一套内容：标题、时长和分值、姓名栏、题目，可附答案页。

  - 真题：换好题号的原卷裁图，按原卷的实际大小放（字号和原卷一样）。太长的裁图切成不超过半页的几段，切在最长的空白中间（通常是小问之间），段与段之间不留间距。

  - 页脚有页码；A4、2 厘米页边距、Arial。

## 第 36 轮：2026-11-22，用免费层实测出复杂题

用户同意后用 Gemini 免费层（gemini-3.6-flash）实测。题库用 4 份真题重建（2025 MM1、MM2、SM2，2023 SM1，69 道题，难度来自考试报告）。每次按一道真题大题当样板出 7–8 分的难题。

**第一轮（改进前，3 道）**

| 要求 | 结果 |
|---|---|
| 仿 2025 MM2 B4（19 分，函数），换情境 + 带图 | 两次都被拦下：只把 sin(x)+1 改成 2sin(x)+1、2cos(x)+1，题干结构和样板一样，没有换情境。放弃 |
| 仿 2025 SM2 B3（微分方程），加难一步 + 结合向量 | 通过。带空气阻力的抛体：解两个微分方程、求位置向量、Euler 法、最大高度。逐小问人工验算全部正确 |
| 仿 2025 MM1 Q9（7 分，得分率 27%），加难一步 + 结合求导 | 本地检查和独立重做都通过，答案也对，但实际是原题把 1 换成 2、w 换成 2k，小问一一对应，并没有加难。原来的照抄检查只看题干措辞和数字，没拦住 |

**发现的两个问题和修法**

1. **重出时没有告诉模型原因**：第二次出题用的是一模一样的请求，模型很容易犯同样的错。现在重出时把没通过的原因和上一次的题干一起发过去，要求换函数类型或情境。
2. **只换字母和数字的题拦不住**：新增“骨架”比较，把数字和单个字母（参数名）换成占位符、去掉 LaTeX 命令名后，比较题干和每个小问。题干相似、六成以上小问一一对应时：要求“加难一步”或“换情境”的直接拒绝，普通仿题提醒老师。用题库里 23 道有小问的真题两两比较（506 对），没有误报。

**第二轮（改进后，重做第一轮没达标的 2 道）**

| 要求 | 结果 |
|---|---|
| 仿 MM2 B4，换情境 + 带图 | 第一次就通过。f(x)=2sin(2x)+2，求解方程、切线、用二次函数求参数、两曲线围成的面积。人工验算全部正确，图和题目一致（两曲线在 0 和 π/4 相交，中间 g>f）。情境还是三角函数，变化不算大 |
| 仿 MM1 Q9，加难一步 + 结合求导 | 第一次又是只换字母，被新检查拦下；带着原因重出后通过：三次函数和水平线交点个数随参数变化，答案正确。和原题考同一个能力但结构不同；难度判断不比原题高，g(x)=2k³−c 这种写法也不像 VCAA |

**用量**：两轮共 13 次左右调用；第一轮约 6.8 万 Token，第二轮约 4.3 万 Token（按付费价约 $0.12）。免费层不收费。

**结论**

- 出的 4 道题数学上全部正确，独立重做全部一致，图形和题目一致。
- 弱点在“像不像新题”和“够不够难”：模型倾向于贴着样板改参数；要求加难时，实际难度常常没上去。现在能拦住贴着改的，但“难度够不够”还只能靠老师审核。
- 图的横轴是 0.5、1、1.5，三角函数题 VCAA 习惯标 π/4、π/2…，可以改进。
- 新增的检查写进 `tests/paper-check.js`（用自编的文字，不是真题）。

## 第 35 轮：2026-11-22，网站版（Wix）

**做法**

- 整个 index.html 放进 Wix 的 HTML 组件里运行：组件里粘贴一个小加载器（`wix/html/loader.html`），从 GitHub Pages 取回 index.html。这样切题、分类、裁图仍在老师的浏览器里算，不受 Wix 后端 14 秒的限制，以后改功能也只改 index.html。
- 用加载器而不是直接填网址：官方只说明了“代码”方式下 HTML 组件和页面代码之间怎么传消息，填网址的方式没有说明。
- 页面和后端之间只用 postMessage：页面代码（`wix/pages/vce-app.js` + `wix/public/vceHost.js`）只转发，后端只接受列出的方法。
- 题库：第 34 轮的题库接口加了 Wix 驱动，五张表对应五个集合，整条记录存成 JSON 文本，文件放媒体库（原卷私密）。批量读取一次一个调用，避免逐条读太慢。
- 文件上传：先用 `getUploadUrl` 在浏览器直接上传；失败（比如跨域不允许）就经后端转存，同一次打开期间不再试直接上传。下载同理。
- AI：页面没有 Key。Gemini 请求交给后端：建任务、后台调用、页面每 2.5 秒取结果。大于 200KB 的文件（整份 PDF）先传到媒体库，后端取回再发给 Gemini，用完删掉。后端返回 Gemini 的原始状态码，页面按本地版的规则提示（额度、Key 无效等）。
- 权限：每个后端方法都检查会员角色，只有 Admin 和 Teacher 能用。操作人以后端写的会员 ID 为准。

## 第 33 轮：2026-11-22，裁图对账，向 100% 准确靠近

**怎么判断裁图对不对**

以前只能人眼看裁图。这一轮加了自动对账（`auditCrops`），每份试卷切完马上做，逐页检查三件事：

1. **漏掉**：页面上的墨迹要么进了某道题的裁图，要么属于已知可以去掉的东西（页眉页脚、页码、Section 标题、续页提示）。两样都不是的，就是漏掉的内容。只有长横线的一段不算。
2. **重复**：两道题的裁图范围重叠超过 2%。多题共用的材料是有意放进每道题的，不算重复。
3. **误涂**：去掉侧边竖条和灰色边框时，按原分辨率检查竖条旁边有没有涂掉文字或表格线。
4. **误擦**：裁图中间被当作噪声擦掉的一行，如果既不像页眉页脚和续页提示，也不是答题横线，就可能是题目内容。

查出问题的题会显示“裁图请看一眼：…”，并写进导出和题库（`crop_flags`）。所有被擦掉的文字也会列出来，方便人工核对。

第 4 项是看了擦掉的文字清单后才加的：清单里三处可疑文字（都在扫描件上）截图核对后都是真问题，见下表最后三行。

为了确认对账真能查出问题，测试时故意制造了错误：左边多涂 11% 报了 23 处，续页起点下移报了 10 处，正常运行报 0 处。

**对账和人工看图找到并修好的问题**

| 问题 | 例子 | 修法 |
|---|---|---|
| 跨页题的后半页只从第一行文字开始裁，上面的表格边框被切掉 | 2025GM1 Q39 | 续页从页眉下方开始裁。只用于本题自己的续页，共用材料不往上扩，否则会和上一题重叠（对账查出过这个问题） |
| 去侧边竖条时，紧贴竖条的字母左边和表格边线被涂掉 | 2025GM1 第 7 页 | 竖条边缘改用原分辨率逐列确定：从竖条内部往外走，遇到第一列不是竖条的就停 |
| 文字列被当成灰色边框 | — | 边框要求是连续的长竖线，不再只按深色像素的总数判断 |
| “This page is blank.” 留在上一题的裁图底部 | 2025MM1 Q8，2025NGM2 Q3、Q12、Q15 | 加进噪声行 |
| 大写的 “CONTINUES OVER PAGE” 留在裁图里 | 2023GM2 Q11、Q13 | 加进噪声行 |
| 扫描件题目里的表头 “Question 1 2 3 4 5” 被当成读错的题号丢掉，又被当噪声涂白 | 2025NGM1 Q30 | 题号往回走的 OCR 行不再丢掉，留在当前题里 |
| OCR 把 “if” 的 f 读成 \(\overrightarrow{1}\)，被当成页码涂掉 | 2024SM2 第 23 页 | 判断是不是纯数字时先把公式转成文字，正文中间的数字不涂 |
| 分母 15 的 “1” 落在页脚高度，被当成页码涂掉 | 2025NMM2 第 7 页 | 扫描件上 OCR 读出的纯数字，只有左右没有紧挨的墨迹才涂（页码周围是空白） |

## 第 30 轮：2026-11-08，按样板出题和带图的题（第三阶段）

- 独立重做时，题目文字里附上图形数据，做题的模型也能“看到”图。
- 打印时图跟着题目一起打印。

## 第 23 轮：2026-11-07，浏览器打印的 PDF（用户的 mock sac.pdf）

这份 PDF 是浏览器打印出来的，公式不是字形：

- ∫ 是一条描边的 S 形贝塞尔曲线，根号是 5 个点的描边折线，高括号是一条弧线，文字层里都没有。根号的顶边还被当成分数线，把上下两行拼成了分数。

## 第 20 轮：2026-11-07，非 AI 模式还原公式

之前题干里的公式是乱的：分数被拆成三行，π、√ 直接丢失，负号和等号可能写错。

**查出来的原因**

- `getTextContent` 会拆散公式，只能改读绘制指令，拿到每个字形的真实坐标。
- 公式字体按页重新编号，同一个控制字符在不同页是 =、+ 或 ∈。旧代码写死 `\u001f → =`，是错的，已删除。
- π、× 等斜体符号靠剪切矩阵实现，被当成旋转文字过滤了。
- 根号是填充多边形，矩阵方括号是 L 形多边形，部分 = 和 − 是细线，都不在文字层。
- Word 导出的 PDF（Cambria Math）把 A、B、C、D 都标成 A，i、n 标成 s，ToUnicode 不可信。
- 子集字体可能把符号放在空格的编码上，不能只看 Unicode。

**做法**

- 符号按字形图像和参考表比对。Symbol 表有 152 个字形，Cambria Math 表有 188 个。
- 还原分数、根号、上下标、积分求和上下限、矩阵及行列标签、分段函数、向量箭头、带边框的表格（含合并单元格）。
- 图内坐标标注不进题干。铺满页面的背景图和方格纸单独处理。
- 分类词典先把 LaTeX 还原成普通文字。

**验证（2025 Methods Exam 2、2025 General Exam 2、2026 EAST SM Mock SAC 1）**

- 守恒检查：约 32,900 个字母、数字和运算符，每页逐字符核对，没有丢失。差异都能解释：两处线条画的 = 是还原出来的，一处 0 是 PDF 重复绘制，方格纸内的标注是按设计移出题干。
- 445 段公式全部通过 KaTeX 严格解析，没有题被标记。
- 已知符号比对 101 个全对。

- 第一轮分析增加 `figures`：每张图所在的 PDF 页、描述和所属小问。
- 第二轮定位：用 PDF.js 渲染含图页面，发给 Gemini 取 `box_2d`，再在浏览器裁剪成 PNG。
- 卡片显示截图，支持调整、删除、手动添加。
- 新增“导出 ZIP（含图片）”；JSON 内嵌 base64；CSV 写图片文件路径。

**查证后做出的决定**

| 决定 | 原因 |
|---|---|
| 渲染页面后裁剪，不提取 PDF 内嵌图片 | 函数图、电路图常是矢量图，扫描件整页是一张图，提取不到 |
| 定位时发页面图片，不发原始 PDF | 官方只为图片说明了 `box_2d`，没有 PDF 的说明；而且坐标必须和裁剪的图一致 |
| 每批最多 6 页合并请求 | 节省频率额度；官方说明内联请求总大小上限 20MB |
| 坐标四周外扩 12（千分比） | 避免切到坐标轴和标注 |
| 定位失败不影响分类结果 | 分类先展示；失败时提示手动框选 |
| 429 带 `retryDelay` 时自动重试一次 | 第二轮更容易碰到频率限制，等待不超过 60 秒 |
| 渲染用 `intent: 'print'` | 默认依赖 `requestAnimationFrame`，页面在后台时渲染会暂停 |
| Wix 暂不迁移截图 | 先验证定位精度，再决定怎么迁移 |

**测试情况**

- 真实渲染：手写的两页 PDF 经 PDF.js 渲染，模拟坐标裁剪，确认矩形位置正确。
- 模拟响应：第二轮 503、429 重试、取消、坏坐标、页码越界、找不到图、无图试卷、PDF.js 不可用。
- 导出：解开 ZIP 检查文件清单和 PNG 文件头，检查 CSV 路径和 JSON 内嵌图片。
- 手动框选：拖动逻辑用程序生成的 pointer 事件测试（面板隐藏，无法用真实鼠标），`setPointerCapture` 被替换，没有实测。
- **没测过：** 真实 Gemini 定位，所以定位精度还没有数据；`figures` 和 `FIGURE_SCHEMA` 也未经 Gemini 实际校验。

## 第 1 轮：2026-11-06，初版 demo 和 Wix 迁移代码

**完成内容**

- `index.html`：上传 PDF、调用 Gemini `generateContent`、结构化返回、卡片审核、导出 JSON/CSV、耗时和 Token 统计。
- `wix/` 和 `WIX_GUIDE.md`：Velo 迁移代码和步骤。

**查证后做出的决定**

| 决定 | 原因 |
|---|---|
| 默认模型 `gemini-3.6-flash` | 官方标记为稳定版，有免费层；`gemini-3.8-flash` 较新，标记为 New |
| 继续用 `generateContent` | 官方推荐新项目用 Interactions API，但说明 `generateContent` 仍完全支持 |
| REST 字段用 `inlineData` / `mimeType` | `generateContent` 官方示例是 camelCase |
| 不发送 `temperature` | 官方说明 3.6+ 会忽略该值，未来会返回 400 |
| 不设置 `thinkingConfig` | 各模型允许的取值不同，先用默认值观察 |
| 保留 20MB 上限 | 需求规定。官方写的是 PDF 50MB，以后可以放宽 |
| `topic` 不用 schema 枚举 | 80 个枚举值有触发 schema 过大的风险。改由提示词约束，前端校验并标红 |
| 公式定界符用 `\( \)` | General Maths 的 `$` 金额不会被误判成公式 |
| Wix 改成任务 + 轮询 | Wix 后端请求上限 14 秒且无法提高 |
| Wix 用 `wix-secrets-backend.v2` | 旧的 `getSecret` 已标注弃用 |

**测试情况**

- 真实接口：用无效 Key 调用，确认浏览器跨域可用、Key 错误提示正确。
- 模拟响应：覆盖 429（频率、日额度、零额度）、413、400、404、503、`MAX_TOKENS`、`RECITATION`、请求拦截、坏 JSON、断网、取消、超大文件、错误文件类型、分类表错误、编辑、确认、导出。
- **没测过：** 真实 Key 下的 PDF 分析，所以 `responseSchema` 尚未经过 Gemini 实际校验，分类效果也还没有数据。
- Wix 代码只做过语法检查。
